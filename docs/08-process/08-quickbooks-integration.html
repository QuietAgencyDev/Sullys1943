QuickBooks Integration

Sully’s ledger → QuickBooks Online · after Helcim banking is live

Gym: Sully’s Boxing Gym (1943) Doc: Separate from demo + banking PDFs Date: August 2026 Audience: Owner + accountant + Quiet Agency
Order of operations: Finish Banking & Payment Setup (Helcim) first. QuickBooks receives settled totals from Sully’s — never card numbers, never membership status as the source of truth.

1. Goal

Keep day-to-day gym ops in Sully’s (memberships, desk CASH/CARD, waivers, walk-ins, owner analytics). Push clean accounting data into QuickBooks Online (QBO) so bookkeeping stays accurate without double-entry at the desk.

2. What stays in Sully’s vs QuickBooks

Data Sully’s (source of truth) QuickBooks
Member / youth / adult profiles Yes Optional Customer names only
Membership active / past_due Yes No (income only)
Waivers, check-ins, XP Yes No
Desk CASH / CARD / Helcim settlement PaymentEvent ledger Sales receipts / deposits
GST/HST, chart of accounts No Yes (accountant-owned)
Payroll, rent, vendors No Yes

3. Prerequisites (owner)

  • QuickBooks Online company created for Sully’s Boxing Gym
  • Chart of accounts reviewed with accountant (CAD)
  • Helcim merchant live (or at least sandbox validated) — see Banking PDF
  • Owner desk showing cash vs card revenue correctly for 1–2 weeks
  • Admin Intuit account that can authorize apps (company admin)

5. Integration phases

Phase A — Manual export (fastest, safe)

  1. Owner desk → review “Money to Sully’s” (today / month by tender).
  2. Quiet Agency adds CSV export: date, type, tender, amount CAD, membership product, externalId.
  3. Import into QBO via Sales → Import or accountant spreadsheet.
  4. End of day: cash drawer count must match Owner “CASH” total.

Phase B — Nightly sync (recommended production)

  1. Create Intuit Developer app → QuickBooks Online → OAuth 2.0.
  2. Owner authorizes Sully’s app once (redirect to staff/owner admin).
  3. Store tokens encrypted in Railway secrets (never in git / browser).
  4. Nightly job posts SalesReceipts / JournalEntries for completed PaymentEvent rows not yet synced.
  5. Idempotency key = PaymentEvent.externalId (no duplicates).
  6. Owner UI shows QuickBooks: Connected · last sync · errors.

Phase C — Optional Helcim ↔ QBO

Helcim may offer its own QBO sync for card settlements. If enabled, do not double-post the same card sale from Sully’s and Helcim. Prefer: Sully’s posts membership/drop-in income; Helcim feeds bank deposit / fee detail only — or Sully’s alone posts everything and Helcim sync stays off.

6. Secrets for Quiet Agency

Env var Where Purpose
QUICKBOOKS_CLIENT_ID Railway API Intuit app client id
QUICKBOOKS_CLIENT_SECRET Railway API Intuit app secret
QUICKBOOKS_REALM_ID Railway API Company id after OAuth
QUICKBOOKS_REFRESH_TOKEN Railway API (encrypted) Long-lived refresh
QUICKBOOKS_ENV=sandbox|production Railway API Target Intuit environment
QUICKBOOKS_SYNC_ENABLED=true Railway API Feature flag
Never put QuickBooks secrets in Vercel web/staff public env. OAuth callback may live on API: e.g. https://api.sullys1943.com/api/v1/integrations/quickbooks/callback

7. Owner connect checklist (when Phase B ships)

  1. Sign in Staff as owner@sullys.local (or live owner account).
  2. Open Owner desk → QuickBooks → Connect.
  3. Approve Intuit permissions for the Sully’s company.
  4. Confirm chart mapping screen (income accounts).
  5. Run Sync now for yesterday’s completed payments.
  6. In QBO, verify one cash drop-in and one card/membership sample.
  7. Turn on nightly sync; leave QUICKBOOKS_ENV=sandbox until samples look right.

8. What we will not sync

  • Card PANs / CVV / Helcim vault tokens
  • Waiver PDFs or medical notes
  • Coach notes, XP, class attendance
  • Passwords or QR check-in tokens
  • Pending / failed payments (only completed)

9. Acceptance tests

  • Sandbox: one adult membership posts once to correct QBO income account
  • Sandbox: youth membership maps to Youth income
  • Desk CASH drop-in → Undeposited Funds (or agreed cash account)
  • Desk CARD / Helcim → clearing + fees treated correctly
  • Refund creates matching credit / negative sale
  • Re-run sync does not duplicate (same externalId)
  • Disconnect OAuth stops posts; reconnect resumes
  • Owner desk shows Connected + last successful sync time

Helcim first · Sully’s remains source of truth · QuickBooks later

Rule: Helcim (or any bank processor) is a service. Membership status, waivers, XP, desk cash sales, and owner analytics live in Sully’s. Never store card numbers in our app.

2. Open Helcim (owner steps)

  1. Go to helcim.com → create a Canadian merchant account for Sully’s Boxing Gym.
  2. Complete business KYC: legal name, GST/HST, void cheque / bank account for deposits, owner ID.
  3. Ask Helcim for a TEC quote using your mix (memberships ~70%, drop-in ~15%, kitchen/merch ~15%).
  4. Enable products you need:
    • Online payments (HelcimPay.js / Payment API)
    • Recurring billing (plans + subscriptions)
    • Smart Terminal or card reader for front desk
    • Webhooks
  5. In Helcim dashboard → Integrations / API, create API credentials for production and keep a separate sandbox set for testing.

Banking checklist

  • Business bank account ready for Helcim payouts
  • Void cheque / direct deposit form submitted
  • GST/HST number on file
  • Statement descriptor agreed (e.g. SULLYS BOXING)
  • Chargeback / fraud contacts named (owner + Quiet Agency)

3. Secrets to give Quiet Agency (never commit to git)

Store only in Railway (API) and Vercel env — not in chat logs long-term.

Env var (recommended) Where Purpose
PAYMENT_PROVIDER=helcim Railway API Feature flag off mock / Stripe-first path
HELCIM_API_TOKEN Railway API Server API auth
HELCIM_ACCOUNT_ID Railway API Merchant account id
HELCIM_WEBHOOK_SECRET Railway API Verify webhook signatures
HELCIM_TERMINAL_ID (optional) Railway API Desk Smart Terminal
NEXT_PUBLIC_HELCIM_PAY_TOKEN (if required) Vercel web only Hosted fields / HelcimPay.js — never the secret API token
Do not put HELCIM_API_TOKEN in the staff or web client. Desk CASH continues to write to Sully’s ledger without Helcim.

5. Front desk hardware

  1. Order Helcim Smart Terminal (or approved reader) for reception.
  2. Pair device to the Helcim account; note terminal ID for env.
  3. Train desk staff:
    • CASH → Staff app drop-in CASH (drawer + Sully ledger)
    • CARD → Terminal tap/chip, then confirm in Staff (or auto via API)
  4. End-of-day: cash drawer count vs Owner “today · CASH” total.
